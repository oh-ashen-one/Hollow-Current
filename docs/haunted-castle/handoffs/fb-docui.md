# fb-docui: document / note UI redesign (owner feedback item 10)

Branch `hc/fb-docui`. Renderer-only: no scene, prefab or gameplay change, so **no bake is needed**; the integrator needs a normal player build.

## What the owner saw (screenshot 2026-10-15 19:06)
Torn beige card on the castle backdrop, tiny kicker, big plain Georgia title, thin rule, body that repeated the heading as "BLOOD LEDGER / THE STEWARD",
huge empty lower half, feather corner ornament, red wax blob, boxed web-style "FILE & CLOSE  ESC", footer "Recovered documents remain listed...".

## What changed
| File | Change |
|---|---|
| `Assets/HollowCurrent/Core/DocumentText.cs` (new, engine independent) | Parses a note into kind (Ledger, Letter, Inscription, Tally, FieldReport), kicker, heading, subject and logical body lines. The baked body header ("BLOOD LEDGER / THE STEWARD", "THE MARGRAVE'S GATE", "BLOOD LEDGER, LAST PAGE IN THE STEWARD'S HAND", "A FAMILY OF FOUR") is consumed and shown **once** as the heading; the card title never repeats it. Done in the renderer because the castle bodies are baked into `Castle.unity`. |
| `Assets/HollowCurrent/Runtime/DocumentUi.cs` (new) | The reader. Full-bleed paper per kind, own word wrap (<= ~70 chars, body 26-28 design units = 31-34 px at 1920x1080), drop cap on ledger pages, red ledger margins and ruled lines, handwriting jitter (baseline +-1.4 units, rotation +-0.5 deg, per line) for letters/tally, centred caps for the inscription, typed header + SUBJECT line + taped print + "FIELD TRANSCRIPT" for Bellwether, scrolling in whole lines (wheel, Up/Down, PageUp/PageDown/Space, Home/End, controller stick) with a "more below" cue, quiet "ESC · set the page down" line at the bottom edge (pad: B / circle). Draws in screen pixels (GUI.matrix reset) so type is crisp. Also draws the journal note rows. No wax blob over text: the only seal is baked into the letter sheet's bottom-right margin and is broken. |
| `Assets/HollowCurrent/Runtime/Interface.cs` | `Note()` now calls `DocumentUi`; the old card is kept as `NoteLegacy()` and used only if a paper sheet is missing. Close line is hit-tested with `TitleHit` (mouse, keyboard focus, controller confirm). Journal's recovered-documents block: kicker + three `JournalDocRow`s in the same faces (castle: IM Fell italic; Bellwether: Courier Prime bold), "read again / not yet found". |
| `Resources/UI/Fonts/` | `IMFellEnglish-Regular/Italic.ttf`, `LaBelleAurore-Regular.ttf`, `CourierPrime-Regular/Bold.ttf` + their `OFL-*.txt` and `.meta`. All SIL OFL 1.1, unmodified Google Fonts files. Logged in `ASSET_LOG.md` and `ASSET_LICENSES.md`. |
| `Resources/UI/Documents/` | `DocLedger.jpg`, `DocLetter.jpg`, `DocField.jpg` (2048x1152): procedural paper (fibre, foxing, tide ring, blood, ink blots, charred edge; folds + seal for the letter; punch holes + coffee ring for field). Generated by `tools/docui_paper.py` (fixed seeds). |
| `Tests/RulesTests.cs` | `DocumentTextTests`: every castle ledger title parses with kicker != heading and no header left in the body; letter, inscription, tally, Bellwether subject, null note. |
| `tools/docui_mock.py` | PIL mock of the screens with the real note texts and fonts (mirrors `DocumentUi.cs` coordinates). |

Fallbacks: a missing font falls back Fell -> Cinzel -> interface serif (and Belle -> Fell italic, Courier -> Cinzel); a missing sheet returns false from `DocumentUi.Draw` and the legacy card is drawn. `HC_DOC_UI fonts_complete=... paper=...` and `HC_DOC_OPEN kind= title= kicker= heading= lines= visible= scrollable=` log once per load / note.

## Item mapping
1. Castle notes: vellum sheet, IM Fell English (ledger, inscription), La Belle Aurore handwriting (letter, tally), dark-red title, faded black-brown body, drop cap, margins >= 400 design units each side of an 800-860 wide column, no duplicated header, small quiet close line, no wax blob.
2. Bellwether: modern ruled notebook sheet, Courier Prime typescript, typed office line / EXHIBIT tag / SUBJECT line, the existing `Surfaces/FamilyPhoto|ChildDrawing|FurnaceDiary` art kept as a taped print beside a "FIELD TRANSCRIPT" column.
3. Journal note list: same faces and colours (see above).
4. Readability (measured, `python3 tools/docui_paper.py --check`, worst 0.5 % of the text-zone pixels): body 5.7:1 (ledger), 6.5:1 (letter), 11.7:1 (field); titles >= 4.9:1; kickers >= 4.9:1; close line >= 5.2:1. Stains, foxing, folds and seal are held outside the text zone (design x 330-1270, y 96-806). Long notes scroll, never overflow.
5. Verification below.

## Verification done (no engine launched)
- `INPUT_SYSTEM_REFERENCE=... python3 tools/check_source.py` PASS (1155 rule assertions incl. the new DocumentText ones; player + editor compile; only the known CS0649/CS0162 warnings).
- Mocks (owner can approve the look first), all 1920x1080, in `docs/haunted-castle/rounds/r13/`: `docui_mock_castle_ledger.png` (the steward), `docui_mock_castle_letter.png`, `docui_mock_castle_inscription.png`, `docui_mock_castle_tally.png`, `docui_mock_bellwether_photo.png`, `docui_mock_bellwether_briefing.png`. Not mocked: the journal list rows and the scroll state (no shipped note is long enough to scroll at the shipped sizes; the Bellwether briefing uses 13 of 14 rows).
- The mock is PIL, not the engine: kerning and baselines can differ by 1-2 px, and a 0.45 px blur imitates ink soaking in (the game draws crisp type).

## What the integrator must run (needs a player build of this branch)
1. Build, then castle ledger + all castle notes at the shipped size, using existing modes:
   `~/.cache/gpu-slot/bin/gpu_slot.sh capture --label fb-docui -- "<Hollow Current.app>/Contents/MacOS/Hollow Current" -hc-playtest <outdir> escape -screen-width 1920 -screen-height 1080 -screen-fullscreen 0`
   `PlaytestDriver.Use` already screenshots every note it opens (`NN_note_Gate_keeper's_letter.png`, `NN_note_Ledger__the_steward.png`, ...). Windowed, `open -g`, no mouse grab (scripted runs consume real input).
2. The Journal screen with a note filed: `-hc-capture <outdir> -hc-capture-shots S8 -hc-capture-size 1920x1080` (S8 opens the steward ledger from the journal and shoots `S8_journal_ledger`; then the journal list can be shot by closing the note, or skip).
3. Bellwether: `-hc-verify -hc-ui-only` captures `ui-note` (Child's drawing, art note) and `Foyer letter`.
4. Check the log for `HC_DOC_UI fonts_complete=True ... paper=True` and one `HC_DOC_OPEN` line per note. If `fonts_complete=False` the .ttf imports did not run (re-import) and the fallback faces are in use.
5. Compare the captures to the mocks. Things I could not see: Unity's dynamic-font baseline against the ruled lines (rules are drawn at baseline + 6 units for ledger, + 4 for field; shift `+ 6f` / `+ 4f` in `CastlePage` / `FieldPage` if text visibly rides the line), IMGUI text colour in linear colour space (colours follow the existing `Label` convention: plain sRGB for text, `.linear` for panels), and JPEG import compression of the sheets (meta uses the project default, quality 50 normal; raise to 100 if banding shows in the vignette).

## Risks
- Everything visual is unverified in the engine; the layout is deterministic from the mock's constants, but font metrics come from hhea ascent (`AscFell` .905, `AscBelle` 1.077, `AscCourier` .781) assuming Unity's face-ascender mode (`ascentCalculationMode: 1` in the font metas).
- The paper sheets are crop-filled like `Backdrop`; on 16:10 windows ~5 % of the width is cropped (nothing important sits there).
- Texts keep straight apostrophes from the source; Fell and Belle render them fine.
- `Resources/UI/Documents/*.jpg` add ~1 MB; fonts ~1 MB.
- Dead-letter: the old FILE & CLOSE `Action`, `Brand`, footer remain in `NoteLegacy` only.
